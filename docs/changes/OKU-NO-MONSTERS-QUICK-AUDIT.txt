Fixed-position repeat passed the explicit zero-monster assertion. It measured
CPU 42.3 ms versus GPU 13.0 ms, with 4,197 remaining things. All five lighting
cache stages hit; renderer loading fell to about 2.65 s (runner load 3.0 s),
but steady rendering remained CPU-bound. The harness still labels its four
samples east/north/west/south when -at forces the same east-facing camera;
these repeat rows are repeated samples, not four different directions.

Across the sweep, geometry trace averages include flats 4.60 ms, walls 3.89 ms,
surface lights 1.67 ms and actors 6.31 ms. These nested timings must not be
added to the inclusive CPU/geometry totals.

Do not take the automatic report's "mostly finding wall blockers" wording
literally: lightsMs combines light collection and light-word packing. The
slowest view has zero final dynamic lights; the counter does not establish
that blocker traversal itself caused the cost.

Startup and stutter
-------------------
An isolated empty diagnostic cache caused a cold lighting bake: about 16.3 s
inside renderer loading, including about 9.7 s for 97,347 static lights
(94,426 window panels), plus about 2 s each for bounce and sky/occlusion.
This does not mean the user's existing cache misses every launch.
It also does not account for all process startup time.

After startup, sampled paused relight stages were small (median 0.035 ms,
maximum 0.073 ms in the selected middle-of-sweep trace). This does not test
active moving-sector relighting. The screenshot frame incurred an approximately
890 ms capture/readback interval; exclude that diagnostic artifact from claims
about gameplay stutter. View changes and effect isolation also invalidate a
continuous-gameplay p95/p99 interpretation of this sweep.

Prioritized follow-up
---------------------
1. Investigate caching static floor/wall batches and limiting rebuilds to changed
   sectors. geometry.cpp currently visits all subsectors and map lines. Triangle
   submission stays around 121k-123k despite different positions/directions.
   Measure a conservative visibility/cache change at these same coordinates.
2. Profile remaining item/decoration presentation before expanding monster
   optimizations. The actor stage still costs about 6 ms without monsters;
   geometry.cpp scans sector thing lists and prepares lighting/presentation.
3. Split light collection/packing and geometry timing further. Retain this
   profile's bake-only lighting when testing; don't assume the reported lightsMs
   is pure dynamic-light blocker work.
4. Record a normal-rendering traversal through the exact reported area and
   moving-sector triggers to attribute intermittent stalls. Keep cold startup,
   screenshot readback, view-sweep measurements and live gameplay separate.

Diagnostic runner repair
------------------------
The original perf runner called G_DeferedInitNew. G_DoNewGame clears nomonsters,
so its reload spawned monsters even with -nomonsters on the command line.
Stopped and excluded that run; retained logs under invalid-monster-reload/.
The test-only runner now uses G_InitNew for map changes and asserts both the
nomonsters flag and zero monster actors when -nomonsters was requested.
The native game/launcher and production performance behavior were not changed.
Rebuilt doom-perf-smoke successfully; completed the corrected coarse sweep.
The final fixed-position repeat completed with the new invariant enabled.
Both diagnostic game processes exited; no audit process remains running.
